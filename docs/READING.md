# Watching a film through its reel

`reel watch` gives an image-and-text reader 30-second pages and a line for each shot in `stream.md`. Read them in
time order. A frame shows one moment. A sound label is an estimate. You can describe a change even when its source
is unclear. A reader with audio input can also play the bounded WAV from `reel listen`.

## Watching a little at a time

For a video tagged with PQ or HLG transfer, Reel renders the stills, frame sheets and magnified details for an sRGB display. FFmpeg uses the frame’s colour information and perceptual tone mapping to fit HDR highlights into that display. A native movie player can render the playable excerpt for its own display. Check `picture_rendering` in a playback turn or run `reel doctor` to see whether the installed FFmpeg supports the conversion. Older builds show the encoded levels. [FFmpeg scale rendering intents](https://ffmpeg.org/ffmpeg-filters.html#scale-1)

For independent first impressions, open the same film in fresh `play` or `mcp` sessions. The presenter can select `--tracks picture`, `--tracks sound` or `--tracks both` (the default). The displayed frames retain their timestamps and the recording retains its channel order and sample times. A track that starts late or ends early keeps its place on the film clock. In a sound-only viewing the inline spectrum depicts the recording. Picture-only playback omits the audio, including on repeat listens. Only a selected track can trigger an early pause. Use the same `--until` and continuous step for comparisons, and check the returned time ranges when a multichannel WAV reaches the MCP byte limit.

A file can contain alternative angles, dubs or commentary. For each medium Reel chooses the first stream with the default disposition, falling back to the first eligible stream in file order. A cover stored as an attachment and a thumbnail track carry no timed picture here. Speech, audio measurements, magnification and playable excerpts all follow the chosen streams. A player configured for a particular language or accessibility option may choose a different track. [Matroska track flags](https://www.matroska.org/technical/notes.html#track-flags)

A bounded snapshot keeps a picture if its presentation on Reel’s microsecond clock began before the stop. The source timestamp of the last picture is available in `current_frame.pts_us` when a picture is still on display. The stored Matroska clip rounds packet times to milliseconds. Full-range camera footage keeps its range on export. For speech or source separation in a time window, Reel cuts the native samples before converting them to the rate required by the model. A sound immediately outside the window cannot enter the conversion filter.

Read `audio.pitch_contour` to follow a repeating sound in the original channels. Each entry in `hz` covers one consecutive window of about 50 ms. The first window starts at `first_window_sample_on_film / rate_hz` and may have begun in the previous turn. A null entry or omitted channel means the recording gave no clear estimate. Period estimates cover 60–2000 Hz. An isolated higher tone can be measured up to 20 kHz if the recording supports it. Noise, overlapping tones and transients can leave gaps or produce misleading repeats. On an exact re-listen the measurements use only whole windows inside the requested samples. `compare_heard` returns the same measurements for both intervals.

A client can launch `reel mcp FILM --until 8.5` over MCP stdio. The presenter chooses the film and the cutoff. Call `view(turn=1)` for the first interval and keep advancing by one. The response contains a JSON text block, inline images in the order listed there and, by default, the interval's original WAV when audio is present. The action strip shows changes in the picture and the channel peaks. The current picture is a preview. `end_of_view` marks the end. Repeating the same turn replays it. The source filename and any later turns stay on the presenting side.

For a host with video input, call `view_media(turn=1, continuous_seconds=5)`. It advances the same clock as `view`, including `--until` and the presenter's track selection. The response gives film times and a resource link. Call `resources/read` and decode the blob. For files above 4 MiB, read the links in response order and append each decoded part to the same file before opening it. The host decides whether to play the file, pass it to a model, or use `view` for a model that accepts images and text. [MCP resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources)

The MOV encodes the displayed pictures in H.264 and carries the released PCM channels. Colours can change during encoding. Frame timestamps are relative to the turn start. A picture already on screen at the start appears at time zero. A picture that starts later keeps its delay. Use `picture_end_s` if a player holds the last picture during an audio tail. A sound-only interval returns a WAV. An interval with neither displayable picture nor recorded samples returns `media: null`. A first advance with `view_media` skips local recognition models. Replaying it with `view` can request listening evidence, or `heard_words` can check speech separately.

A normal view includes both the native-channel WAV and the available local readings of the released recording. For a client that reads pictures and text, start the server with `--image-client`, or set `native_audio=false` on a view to omit the attachment. `sound_estimates=false` suppresses the local interpretations in either mode. The waveform reader can use up to eight seconds of contiguous released audio. A joint read covering the turn already includes an audio-only impression. Speech activity gives possible voice intervals. Only timed words that agreed in two transcriptions are available to quote. Inspect each reader’s status when a helper is unavailable. `audio.wav_attached` records whether this response also includes the WAV. With `--image-client`, both `view` and `observe` attach the WAV on explicit request.

If someone talks about a sound, look for acoustic evidence that it occurred. In each speech window, `outside_speech_activity` lists the gaps around the estimated voice intervals on that channel. Each entry gives film times and either digital silence or the recorded peak level in dBFS. You can replay one of those gaps with `listen`. All-zero samples rule out an event during that gap. Other sounds may overlap the voice, and the detector can miss speech.

The picture-and-text view puts local readings near the beginning of the report. Channel numbers can share a reading when their reported evidence matches. All sound-change times remain available in `audio.band_change_times_s`. In stereo or a named surround pair, `audio.stereo_summary` shows when one channel was louder and when a shared waveform reached one channel first. These can favor different channels. Each time range groups consecutive measurements with the same ordering and gives their smallest and largest difference. An unresolved lag stays unresolved, and equal levels need not mean simultaneous arrival. Replay with `full_detail=true` for the individual quarter-second measurements, correlations, band changes and encoder frame times. Requests with native WAV or with `sound_estimates=false` include those details directly.

For both kinds of client, check `audio.recorded_spectrum` against a proposed sound. It covers the current turn at the source sample rate. Each channel gives RMS in dBFS, the 10th and 90th percentiles of recorded spectral power in Hz and the share in its strongest three adjacent FFT bins (about 94 Hz at common recording rates). A small share can still be the maximum in wideband noise. A narrow peak alone leaves its source open. The estimate uses approximately 32 ms Hann windows with half overlap. A short interval can supply a level before it has enough samples for a spectrum. Silence has a null level. These measurements can include frequencies above the local waveform reader’s 8 kHz limit.

You can direct the next look from the scene currently on screen. For example, `view(turn=2, focus=[0.7, 0.4], max_seconds=0.3)` follows that location for up to 0.3 s. Coordinates are fractions of the full picture, measured from the top left. The crop holds that screen position for this turn, covers a third of each dimension and stays inside the picture near its edges. Its motion strip shares the film clock with the full scene and original soundtrack. For the final exposure, the small overview on the left marks your point and box, and the right side shows the corresponding pixels, scaled down only above 1280 by 960. Yellow ticks outside the crop mark the selected row and column. `point_in_detail` gives that pixel relative to the top left of the crop. The result identifies the frame’s presentation time, the source pixel bounds and the detail bounds in the returned image. On an audio-only turn the focus has status `no_picture`. A saved final picture can still provide the detail if the source for the motion strip is unavailable.

To inspect a movement across a fixed screen location, pass `motion_point=[x,y]` to `view`, `ask_scene` or `observe`, with coordinates from 0 to 1 measured from the top left of the whole picture. On the CLI, use `reel observe DIR --t0 START --t1 END --motion-point X Y`. The small picture marks both lines. Time runs from left to right on both plots. From top to bottom, the upper plot reads down the vertical line and the lower plot reads across the horizontal line from the left. A diagonal in the lower plot can show a sideways movement. Light changes and camera motion also change these pixels.

Each column uses the RGB values from one displayed exposure of the released frame sheets. The plot holds each exposure for its display time and gives even the shortest one at least one column. Read the printed clock for timing. Each page covers at most 240 exposures. A picture held at the start is included. The plot ends with the picture when only sound continues. The crosshair identifies a screen location throughout the interval, including when an object moves away from it.

To keep the same point in view while it moves, add `follow_from_s` to `view`. Use the film time printed on the picture where you selected `focus=[x,y]`. The eight-second window ends at the end of the requested turn. The tracker uses every distinct published exposure starting with the picture on screen at the chosen time, including exposures from earlier turns. Up to six illustrations show the path. A second image pairs the selected detail with the most recent estimated match, including its time if the point has since disappeared. Each detail uses a saved full-resolution still or the original recording at that published time. If the recording has changed or is unavailable, Reel uses the saved frame sheet and identifies it as the source. Check what each point actually falls on. Trackers can slip onto a nearby part of the scene. `current.point=null` means the point could not be located and `current=null` means the turn ended without a current picture. After a long movement, use the time and coordinates of a visible point as the next anchor. You can replay a turn to inspect it without advancing. From the CLI, `reel follow TURN --from 1.25 --point 0.7 0.4` prints the trajectory at the original frame times. Add `--out NEW_DIR` for the pictures. The optional learned tracker is prepared by `reel setup --follow` and can use a separate interpreter through `REEL_FOLLOW_PYTHON`.

A new turn can choose its own point and maximum duration. The duration ranges from one microsecond on the presentation clock to two seconds. An event or the cutoff can pause it earlier. Omitting the duration restores the normal two-second maximum. Replaying a published turn with a different focus keeps its original times and sound. To resolve a detail between the previews, `look(turn=N, at_s=T, box=[left, top, right, bottom])` returns the original pixels from the exposure on display at T. T must precede turn N’s end. Add `read_text=true` to read words and numbers from that crop with Apple Vision. The response includes candidate text, confidence and bounding boxes relative to the crop’s top left. The image is available even when the recognizer has no reading.

When the action strip and final still omit a visible picture change, a normal turn includes the full sequence if it fits on one sheet. For longer runs of identical pixels at preview resolution, the first picture of each run carries its original time and `exposures_per_picture` gives the number represented. Returning to an earlier appearance starts a new run. When the scene has many different pictures you can request a shorter next turn.

On busy scenes, `selected_picture_pts_us` identifies a separate sheet of up to twelve actual exposures in time order. In a region of the picture, Reel looks for an appearance that differs from both surrounding views more than those two views differ from each other. It checks the remaining gaps again after each selection. Other exposures can fall between these timestamps. Use the regular frame pages to inspect them.

When a change is concentrated in one part of a picture that lost detail in the preview, `local_picture_change` gives the box and two film times. Call `look(turn=N, at_s=..., box=[...])` at either time to see the same part of the original frame. Both times are within the released turn. A carried frame can have an earlier `pts_us`. A cut or a quiet scene may have no box. The box measures pixel change. Use the pictures to decide what you saw.

Match the picture timestamp to `audio.during_pictures[].pts_us`. Each row measures one native exposure on the film clock, clipped to this turn. `wav_samples` gives its half-open range in the turn’s WAV, counting from zero. An empty range contains no samples. For a nonempty range, `peak_dbfs` and `rms_dbfs` give one value per recorded channel. A null level means digital silence. Even when identical previews share one cell, the row measures only the exposure at the printed timestamp. Sound between listed exposures is still present in the continuous recording and action strip.

To see successive exposures on the first pass, call `view(turn=1, max_frames=12)`. The first image contains up to twelve time-stamped pictures in reading order, including any picture still on screen when the turn began. `successive_picture_pts_us` gives their original times. If the picture ends while sound continues, `picture_end_s` gives that boundary. When the frame limit ends a turn, the next unseen picture starts the next turn. The WAV contains exactly the samples in the published interval. A time limit, the end of the source, the audio byte limit or the presenter’s cutoff can end a turn sooner. With only `max_frames`, the time limit is two seconds, including through sound-only stretches. Choose a different pace on the next turn or replay an existing turn to receive its original sequence. The CLI accepts `play --continuous --max-frames 12`.

For a longer first impression, use `view(turn=1, continuous_seconds=8)`. Choose a duration from one microsecond through eight seconds. Picture cuts and sound changes stay in the returned interval. The timestamped action strips cover it in order, the WAV retains its native channels, and `frames(turn, page)` lets you revisit each exposure. The source end, the presenter’s cutoff or the four-MiB limit on uncompressed audio can shorten a turn. Read `end_s` for the exact stopping point. Choose either `continuous_seconds` or `max_seconds` on each advance. Replaying a turn keeps its published bounds. In `reel play`, use `--continuous --step 8` to set a fixed pace for the session. The inline audio limit applies to MCP delivery.

When the recorded spectrum changes sharply, `audio.band_changes` gives the film time and channel numbers. Its optional `rise` and `fall` give the frequency range in Hz and the size of the change in dB. A shift from a low tone to a high one can register even if the overall volume stays steady. If pictures were on display, `images_in_order` identifies the strip showing the scene around that change. An offscreen source can coincide with an unrelated movement. Start the server with `--gaze` to receive the recent fixation crops when the local gaze model is available. The attached times identify the actual pictures behind those predictions. A sample marked `centre_fallback` shows the middle of the picture because the gaze model supplied no point. Add `--describe-sounds` to include an impression from the local waveform reader in `sound_descriptions` at each pause, even on an image-and-text client. Each impression states the interval the listener heard, which may include preceding turns. Check `heard_words` before quoting speech.

For finer detail, `frames(turn, page)` returns a timestamped sheet of successive pictures. Pages start at 1. `look(turn, box)` returns original pixels from the current picture at that turn. Both work only on published turns. `heard_words(turn)` checks recent speech through the turn. Use the speech result for words to quote. For speech recognition install the speech extra or point the server’s `REEL_ASR_PYTHON` at a Python that has it. Run `reel setup --speech --describe-sounds` once to prepare the speech recognizer and the waveform reader. When using a separate Python, pass that same environment setting to setup and to the MCP server.

A channel can also report `voice_with_gain` when the detector picks up a possible voice after amplification. Read its times on the film clock. The same gain applies to all channels in that window, up to 40 dB or a peak of −3 dBFS. These estimates can include background noise. Only `words` supplies a transcript, and it uses the recording at its original level.

With the local waveform reader active, a channel may also have `possible_words`. Keep these separate from a verbatim quotation. Whisper timed the word in a gap within detected speech. The second reader heard the same samples on that channel without the picture or any proposed words. Both readings agreed on an already supported word in the same speech interval and on the spelling and order of the addition. A candidate’s timing and `p` value come from Whisper. These matches can still be wrong. If the optional reader is unavailable, use the words from the two Whisper listening windows. `independent_word_check` reports whether a check ran, found no candidates or was unavailable. An empty word list can occur within audible speech.

If you want to form your own first impression, set `sound_estimates=false` on each `view`. The pictures, channel measurements, spectrum and optional WAV are the same. On a later call to the same turn you can request the sound estimates, joint impressions and prepared speech transcript.

Use `view(turn=N, joint_seconds=6)` to follow recent motion with its sound across pauses. The number sets how far back the local reader looks, up to eight seconds from the end of turn N. It hears each distinct recorded channel alone and with the corresponding moving pictures. You can request this while advancing or replaying a turn, including with `sound_estimates=false`. The ordinary images and optional WAV belong to turn N. The longer descriptions are in `joint`, with their own time bounds. An unavailable model reports its status there. The same request at a terminal pause is `joint 6`.

If the event starts or ends inside a turn, use `ask_scene(start_s=2.4, end_s=3.7, question="What moves when the sound changes?")`. Choose up to eight seconds that you have already seen. Read the pictures and channel peaks on the returned pages. The text gives per-channel RMS and peak levels in consecutive half-second spans, with their exact WAV sample ranges. Each entry in `audio.band_changes` gives the film time at the end of the analysis window and the channels that changed. With just the start and end times, Reel returns the pictures and these measurements without loading a local model. A steady recording can have sound throughout and yield an empty list. The local reader hears each channel alone and with the moving pictures. The two descriptions can disagree. The optional `native_audio=true` attaches the original channels for the same span. The range can cross pauses and supports a replay after the source file is closed. A missing local reader leaves the pages and requested WAV available. A picture-only interval returns images and the status `no_audio`. A reader started for a single question closes after the answer. A reader already following the film stays available for playback.

To hear across pauses, call `listen(turn=N, start_s=2, end_s=7)` after turn N has reached 7 s. The local waveform reader hears that interval and the reply includes the channel spectrum. With no times, it hears the specified turn. With only an end time, it starts at the beginning of the turn containing that end. Add `native_audio=true` for the native-channel WAV or `describe=false` for measurements and media alone. If `next_start_s` is set, use it as the next start with the same turn and end. Each reply covers at most 30 seconds, with a shorter limit for large WAV payloads.

To check a sound you think you recognized, add `alternatives=["a rushing stream", "people talking"]` to `listen` with your own descriptions. Read `original_sound_match.windows[].channels[]` for scores in the order you supplied. An empty list requests the nearest sounds from the catalogue. These scores come from the original mix. With a listening component and an available matcher, `component_sound_match` also scores the selected waveform on the same clock. A channel with no signal has no scores. An unavailable matcher leaves the spectrum and requested audio accessible.

To compare sounds on the picture clock, call `ask_scene(start_s=2, end_s=7, alternatives=["water running", "a person speaking"])`. Read `original_sound_match` beside the pictures. Each window gives its film times and offsets into the returned WAV (`wav_samples`, end exclusive). The one-second `windows` start at the requested excerpt and include its last partial second. CLAP repeats short clips to fill its ten-second input and pads the remainder. A rhythmic label on a short clip can come from that repetition. In `continuous_windows`, each channel is read in its original order once, in spans of up to ten seconds. Only unused encoder input is filled with zeros. The film times and WAV sample ranges cover recorded samples only. Compare the longer phrase with what changes across the shorter windows. Several sources can sound alike. Look for independent evidence before linking a sound to a visible action. Use `alternatives=[]` to explore the catalogue without proposing names. On `listen`, select `per_second=true` for the same timing.

When a sound starts or changes in the middle of a scene, choose a replay that includes the sound on both sides. For example, `ask_scene(start_s=2, end_s=4, mark_sound=[2.91,3.14])` adds the original channels' spectra and peak traces on a shared clock. The gold bracket marks 2.91–3.14 s. Brightness covers −80 to 0 dBFS. The spectral display uses centred 25 ms Hann windows. The blue peak trace includes every recorded sample. The mark changes only the diagram. Native audio, speech estimates and comparisons cover 2–4 s. Replay 2.91–3.14 s separately for evidence confined to that sound.

A recording-only replay with no pictures and `native_audio=false` also shows the spectrogram without requiring a mark. In `images_in_order[].recorded_sound_window`, `mark_samples` describes a half-open range relative to this replay WAV. The MCP `listen` tool accepts the same `mark_sound` option. Under `reel listen DIR --t0 2 --t1 4 --mark-sound 2.91 3.14`, `recorded_sound_window.file` points to the diagram. The diagram always uses the original mix, including when the listening request also selects a filtered component.

To see the exact picture that coincided with a brief sound, call `ask_scene(start_s=2.0, end_s=2.3, exposure_detail=true)` after that interval has played. Read the extra sheet left to right, then down. If the interval contains up to 12 displayed exposures, it shows each one. A longer sequence shows six consecutive exposures around the strongest measured rise in a frequency band while a picture was on screen. There is no extra sheet for a longer sequence without a measured rise, a sequence of identical pictures, or a missing sound or picture track. You can request a narrower interval anywhere you have already watched.

The time below each picture marks when it became visible inside the replay. A picture already on screen carries into the first cell. The label gives the loudest channel peak while the picture was visible. `digital silence` means all samples were zero and `no audio sample` means the exposure fell between samples. In `consecutive_exposures.frames`, `pts_us` is the original frame time, `wav_samples` gives half-open offsets into the released recording, and the peak and RMS lists have one level per channel. Timing alone leaves the identity of the sound source open.

To compare movements against a sound, give `ask_scene` a list of `sync_regions`. Enter each rectangle as normalized `[left, top, right, bottom]`. The numbered rectangles on the first and last pictures outline the full areas measured. The coloured traces measure the mean absolute pixel change across each rectangle between successive released exposures. The image metadata gives these bounds in display pixels under `input_rectangles_px`, with exclusive right and bottom edges. Older saved replies use `input_squares_px` for the central square they measured. All traces use the same vertical scale. The channel peaks below use the same film clock. They cover the original scene recording. A change can be caused by camera motion.

With `reel setup --sync`, `region_timing.windows[].channels[].near_zero_mass` gives Synchformer’s score for a timing offset within 0.2 seconds of zero, in box order. A channel can fit several regions even when the source is offscreen. `static_region_indices` indexes that list from zero. The sync reader takes the exposure on display at each 25 Hz tick and compares only concurrent pictures and sound. Below one second it returns insufficient evidence. Below five seconds it reports how much it padded. Longer spans use overlapping five-second windows where needed. The motion diagram is available even when the model is missing.

If several sounds overlap, `component="harmonic"` emphasizes energy that holds its frequency and `component="percussive"` emphasizes short changes spread across frequencies. Both keep the channel timing and use the same filter on every channel without adding gain. Their samples add back to the original within float precision. The filter reads only the returned excerpt. A voice, instrument or machine can be present in both. The returned spectrum, WAV and component levels belong to the selected sound. With `describe=true` the local listener hears the component and the original together and describes what it can identify in the original. Use `component="mix"` for the original on its own. The same choices are available with `reel listen DIR --component percussive` and at a playback pause with `listen --component percussive`.

For a recording with a left and right pair, use `component="mid"` for their average or `component="side"` for half the difference (left minus right). Both output channels play the selected signal in phase, so a mono client can hear it. For named surround pairs the same calculation runs within each pair. Unpaired channels play only in mid. The report lists the pairs used. A sound from one source can reach both components. A mobile recording with a delayed reflection can produce a strong side signal even when nobody moved.

To revisit a movement with its sound, call `observe(start_s=1.8, end_s=2.2)` once playback has reached 2.2 s. You can cross a playback pause or pass a `box` to magnify part of the scene. The response gives you successive frames, the change and level traces, a channel spectrum and the matching WAV. Each entry in `moments` identifies the frame on display and the sample range in this WAV. The optional `box` affects the picture. Sound covers every recorded channel. Each reply covers up to twelve displayed pictures or two seconds, whichever comes first. When `next_start_s` is set, use that time as your next start and keep the same end. Playback stays paused. For an image-and-text client, set `native_audio=false` to receive the printed and visual evidence alone.

A client that accepts audio can decode the standard `audio/wav` content block. A client that accepts images and text can use the spectrum, channel evidence and prepared local readers. Set `native_audio=false` on a view call to omit the WAV. Each client decides which content blocks actually reach its model. [MCP tool result formats](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#tool-result)

Run `reel play FILM --out NEW_DIR`. It also accepts a previously built reel. For a blind first viewing, keep the source
on the presenting side and give the reader only each published directory. The first line on standard output is the path
to its `view.json`. All media paths in it are relative to that file. Open the frame sheets in order, the spectrogram,
and the current picture, or play the WAV if the reader accepts audio. The frequency plot and its time labels start
at the beginning of this interval. The frame labels use the film clock. Pictures are listed at their presentation times,
so a picture held across a pause can appear again. The clock continues when a track is silent or has finished.

At each pause, `audio.signal` reports whether the decoded samples include any nonzero value. This includes sounds too faint to hear. With cached AudioSet weights, open `audio.source_estimates.windows`. The current block starts at `start_s`. Its source candidates may draw on the same channel back to `context_start_s`, up to four seconds in total. A missing model has status `unavailable`. Digital silence needs no classifier.

With `reel setup --captions`, read `audio.scene.windows` in a playback turn or observation and `scene.windows` in a listening result. A local audio captioner gets only the waveform from each distinct active channel. It waits for two seconds of contiguous recording, describes up to ten seconds through the current pause, and forgets old sound across a gap. A long request has several windows. In live playback, an impression can include what sounded before this turn. When that history reaches into an earlier turn, `audio.scene.recent_windows` can also describe just the newly released block. For pauses shorter than two seconds, this second reading uses the last two seconds of sound and updates after at least two more seconds have elapsed. Each entry gives the actual start and end time. A source mentioned only in the wider description may already have stopped. Both descriptions come from the same captioner. An explicit `listen` or `observe` uses only the excerpt you asked for. A channel silent in the new block receives no impression. An empty window list leaves the measured waveform and other senses available. If the model mentions speech, consult the speech evidence before quoting any words.

After hearing an interval, enter `match START END` to retrieve similar sounds without proposing a source. Add quoted descriptions to compare your own ideas. Each channel has a cosine for each supplied description, in order, and the three closest of 527 independent catalogue descriptions. A clear difference between two scores can still leave both descriptions implausible. Keep the source open when the recording and other evidence do not support it. Only a speech read can supply words. A saved reel or playback turn accepts the same operation through `reel match DIR --t0 START --t1 END ["description" ...]`. Add `--per-second` after the two times in either command for consecutive one-second comparisons. On a playback turn the end must already have been delivered.

Let the reader say what caught its attention, or simply keep watching. Write `next` and a newline to the process's
standard input to receive the next directory. `next 0.4` requests at most 0.4 seconds on this advance. The following
advance uses the normal limit again. `quit` or end of input closes the viewing. A program can use the same request and
response loop over pipes without a model-specific service. A reader that accepts text and images can also run
`reel listen TURN_DIR` to obtain local sound estimates for the published WAV. Optional subranges use film times.

To find when a visible change occurred, replay a published turn with `view(turn=N, full_detail=true)`. Each action image lists `rgb_change.pts_us` and a matching `mean_abs_rgb` value from 0 to 255. It is the average absolute difference across RGB samples in the displayed overview, or within the crop on an `observe` replay with a box. The timestamp belongs to the newer picture. A held picture at the start supplies context. If no previous exposure is available, the first picture has no comparison. Multiple source pictures at one display time contribute only the last image. The same measurements accompany `observe` and `ask_scene(exposure_detail=true)`. Older saved playback packets can lack this series.

Open `action_view.pages` in a playback turn to see motion and sound together. Each page spans up to two seconds. In the playback overview and an ordinary MCP `view`, each column shows the scene at its centre. If the first picture in that cell differs, it is shown below as `also seen`. If it matches the centre, a brief local change can appear below instead. A blank view marks an instant with no picture on screen. The longest visible exposure can still appear below it. Read each picture's printed time.

When you revisit an interval with `observe` or magnify a fixed region with MCP `view(focus=...)`, those same pictures appear from left to right in time order. Finish the first row before reading the next. Each label points to its observation time on the row's clock. Orange marks the mean absolute RGB change at each frame transition, up to 32 intensity levels. In `observe`, blue shows each recorded channel's peak from −72 to 0 dBFS. A short last row covers only the time through the requested end. A focused MCP view also includes the ordinary full-scene overview and its sound. The crop does not change the soundtrack.

The JSON for the chronological pages includes `rows[].pictures`. Each entry pairs the observation time (`at_s`) with the native picture timestamp (`pts_us`), which can be earlier if the picture was held. During change-triggered playback, a joint window covers up to four seconds or 48 displayed pictures. Continuous playback and a requested history can cover up to eight seconds or 240 exposures per window. On a regular clock a repeated picture can be held if every change remains visible within 25 ms of its original onset. When a single audiovisual window covers the recording, Reel reuses its open waveform reading. A nonzero excerpt shorter than 25 ms retains its level and the status `insufficient_encoder_input`.

Add `joint_seconds=6` to include earlier turns in the same six seconds. The audiovisual reader answers from each window. Read `joint.recording.windows` for a separate answer from the whole released recording, with no pictures. Each entry gives film times and the channels the reader heard. In the running CLI player, enter `joint 6 What changes when the sound begins?`.

By default the player uses up to 30 seconds of uninterrupted audio leading up to this pause. A turn copied on its own supplies just that turn's sound.

From another process, use `reel listen TURN_DIR --question "Does the tapping get faster?"`. Add `--t0 S --t1 E` for a particular stretch of already delivered audio. An explicit range cannot cross a gap in the retained turns or reach into the future. For a saved `watch` reel, supply both times. Each entry in `sound_descriptions.windows` gives its film times and groups identical channels. Read the group's `answer` for a question or its `impression` for an open description. If you want to hear what someone said, write `speech` to the player. It prints one JSON result and waits at the same moment. With the earlier turn directories available, both commands recover up to eight seconds of contiguous recorded audio. Open `speech.windows` in an automatic playback result, or `windows` in a requested result. Times use the film clock. Each group lists its recorded channel numbers, estimated speech activity, and word candidates with start `t`, end `e`, and Whisper score `p`. A word must match in two overlapping decodes with different boundaries. Distinct channels are checked separately and identical results share a row. If the channels give different words for the same moment, keep that uncertainty when reporting what someone said. Activity with an empty word list means the recognizer could not confirm the words. Empty activity means the detector found no speech there. The WAV can still contain sounds. A later window may revise earlier words as more of an utterance becomes available.

To check speech over an exact interval, call `heard_words(turn=N, start_s=2.1, end_s=4.8)`. The speech reader gets only those recorded samples, even when they span several pauses. The times in `activity` mark estimated voice intervals. A voice may have no recognized words. Only `words` can support a quotation. Asking a question or supplying sound alternatives in `ask_scene` includes a fresh speech reading from the same recording as the pictures.

If a language is known, `heard_words(turn=N, lang="bn")` or `speech bn` in the player rereads the released audio with that language hint. The result records the hint. Asking again without it uses the session’s original language setting. When checking a word, Reel compares the two readings at overlapping times and preserves the marks that distinguish their spellings. A vowel or tone mark split off by the recognizer joins its preceding letter when their times meet in the same transcription segment. The confidence of the combined text is the lowest of its pieces.

The ordinary player advertises the command in `speech.command` whenever it supplies audio. `play --speech` runs the local helper before publishing each such turn. It supports language detection or an explicit `--lang` code and reports `unavailable` if the helper fails. Set `REEL_ASR_PYTHON` to the Python used for Reel’s local speech recognition.

To take a closer look without advancing, write `look LEFT TOP RIGHT BOTTOM` to the player. It prints the PNG path and waits for another command at the same moment. For an invalid box or a pause without a picture it prints a JSON error and keeps waiting. To do the same from another process, run `reel look TURN_DIR --box LEFT TOP RIGHT BOTTOM`. Coordinates are fractions of the current picture, with (0, 0) at the top left. You can inspect another region before you advance.

In the running player, `look --at 1.25 0.2 0.1 0.6 0.5` returns a PNG cropped from the native picture that was on screen at 1.25 seconds. The player finds its presentation timestamp in the already delivered frames, including earlier pauses. The requested time must be strictly earlier than the current pause. The result goes into the current turn. Use `look LEFT TOP RIGHT BOTTOM` for the picture on screen now. A detached turn still supports `reel look TURN_DIR --box LEFT TOP RIGHT BOTTOM` against its saved current picture.

With `reel play --gaze`, read the whole picture alongside `gaze.detail.file` for the suggested detail at this pause. Open `gaze.recent_details.file` to follow up to three closer looks over the preceding second. Each comes from the original picture at that time. The optional local UNISAL model predicts a point from the pictures seen so far. On a uniform picture the point is null.

`gaze.samples` holds each prediction made during the interval. Divide `tick` by `rate_hz` (6) for the time on the film clock. `pts_us` identifies the displayed frame, which may be held across ticks. A point has normalized x and y coordinates from the top left. The recent strip includes its own sample records so it can be read on its own. It can extend into a previous turn. If the gaze helper is unavailable, you can still choose a crop with `look`.

Both `play` and `observe` include `sound_views.events` for audiovisual material. Each event points to the full picture up to 160 ms before and after a measured change in recorded sound. The last panel shows the largest absolute pixel differences between successive views, amplified threefold. Times on the strip use the film clock. Each frame entry gives its requested time and the PTS of the displayed picture. A blank position means there was no picture on display. Motion elsewhere in the scene, camera motion and cuts also appear in the difference image.

Reel measures per-channel band amplitudes in 40 ms windows every 20 ms, with octave boundaries from 125 Hz through 8 kHz where the recording permits. The marked time is the end of the newer window. A change must average at least 3 dB across the bands and reach the median plus three median absolute deviations of the preceding changes in that channel, using up to one second of history. A burst gets a new cue after at least 160 ms since its last threshold crossing. The detector carries its history across pauses. An explicit observation starts fresh at the requested range. The audio lists every registered cue. For the picture strip Reel picks the strongest cue in each three seconds of the delivered interval.

With `--media`, open the `media.file` from the same result to replay the bounded interval. Audiovisual excerpts are QuickTime MOV files with H.264 picture and the excerpt's native-channel PCM. The video keeps its frame times and uses a compressed 8-bit 4:2:0 image for playback. The file's clock begins at the requested interval. A picture already on screen at the start is visible immediately. Check `picture_end_s` on the film clock if the sound continues after the final picture. An audio-only span reuses the WAV.

`--describe-sounds` adds `sound_descriptions` when requested. A local audio-language model receives each distinct
recorded channel separately at 16 kHz. It gets a neutral question and no pictures, file names, or tagger output.
During playback a description can cover up to eight seconds of already presented audio. Check the window's start
and end before attributing a sound to the current frame. With `reel listen` the description uses only the requested
WAV interval. Long queries are split into adjacent windows of up to 30 seconds.

Each channel group has its own `impression` (a source or sound-quality estimate). Digital silence gets a measured
flag at the listener’s 16 kHz input. In a live window with preceding context, `current_start_s` marks the new block and `current_signal` reports whether that channel is active in it. A channel that falls silent gets no new impression. For silence at the source sample rate, read the playback turn’s `audio.signal`. In `measured_profile`, `rms_dbfs` gives the recorded level and `band_power_fraction` gives the share of
power in the strongest 93.75 Hz band below 8 kHz, averaged over the time span shown. Use these measurements to
check a claimed change or sustained tone. An impression alone establishes neither a word nor a visible source.
A missing helper produces an explicit unavailable status while the WAV and frame sheets remain usable.

By default each advance covers at most two seconds. The player checks the pictures and the per-channel recorded
levels in increments of up to 100 ms. With `--pause-on-sound-change` on `play` or `mcp`, a sharp change in the frequency bands can also interrupt playback. Each turn can continue for at least half a second if its deadline permits. The `pause` object gives the reason (`change` for an early stop or `interval` at the deadline) and the first picture, level and band change times that occurred, when present. These pauses are opportunities to react. A sound or movement can extend through several
pauses. Track the same subject across them and revise an earlier impression if new evidence warrants it.

## First viewing at a stopping point

To recheck picture and sound together, choose a short interval and run `reel observe REEL_DIR --t0 S --t1 E`.
In `reel.observe.v1`, each moment starts at `start_s` and ends just before `end_s`. Its one-based page and cell
refer to a picture in the PNG sheets. A missing picture means the video track had nothing on display.
`wav_samples` selects the matching samples in the supplied WAV, counting from zero and excluding the end index.
Per-channel peak and RMS levels describe that span. A null level denotes digital silence. A null audio field means
there are no audio samples to send for this interval. A reader with an audio input can take the WAV along with
the sheets. A reader using images and text can compare the movements with the recorded level changes.

With Synchformer installed (`reel setup --sync`), you can ask whether the timing of motion in a visible region fits the recorded sound. For two candidate regions, the command can be written as follows.

```bash
reel observe REEL_DIR --t0 2 --t1 6 --sync-region 0 0 0.5 1 --sync-region 0.5 0 1 1
```

Use normalized left, top, right and bottom edges in display coordinates. The encoder fits the whole box inside its 224 × 224 input, preserves its display aspect ratio and pads unused space with black. A long, narrow box leaves fewer encoder pixels across its short side. In `region_timing`, each distinct non-silent channel has a `near_zero_mass` value per box in the same order. This sums the model's offset scores between −0.2 and +0.2 seconds. A high value can also occur with offscreen sound, especially when several objects move together. Short windows use held video and silent audio padding up to five seconds. The JSON gives the amount. Intervals shorter than one second return no score. A null score means the encoded crop stayed still. Its zero-based index appears in `static_region_indices`.

For a reel made with `--until`, read the pages in order with their lines from `stream.md`.
After the final page, open `now.png` if supplied. It shows the picture displayed immediately
before the stop, at source detail. The history strip can show an earlier moment in the same shot.
A snapshot that stops in an audio tail has no current picture. Record what you noticed before
seeing a specific question or a later snapshot.

For a program that forwards these inputs, `meta.json` gives the relative image filename in
`current_frame.file` and the source presentation time in `current_frame.pts_us` (microseconds).
`current_frame` is null when the picture has ended. Older snapshots may omit the field.
If something has started but its source is unclear, say what you could tell at this point.

In the mix column, `0:04.00 -56/-32@0:04.58` means that the window starts at 4 s.
Its median 10 ms RMS is −56 dBFS and its strongest bin starts at 4.58 s at −32 dBFS.
Short shots use one-second windows. A long shot uses up to ten longer windows. Each bin belongs
to the window containing its start time. Levels are rounded to whole dB, with a measurement floor
of −120 dBFS. The loudness column gives the shot median of momentary LUFS readings. A dBFS value describes the digital recording. Playback volume at a listener’s ears is unknown.

## How to watch

1. If there is a `pages/page_00.png`, look at it first: it shows what a normal frame of this kind of film looks
   like, the picture a fan of the genre carries in their head. Keep it in mind while watching.
   Do not skim ahead and do not read summaries first. Open `pages/page_01.png`, then the lines of `stream.md` for
   the same 30 seconds, then page 2, and so on to the end.
2. After each page, briefly record what you noticed on first viewing. Describe what changed or stayed the same
   in the scene and what you could hear. Leave room for uncertainty about an object, a word or a sound's source.
3. Keep earlier pages in mind as you watch. Someone or something may return.
4. To inspect a brief moment, use `reel zoom REEL_DIR --t0 S --t1 S`. The page spreads those seconds across its
   full width and selects stills with their presentation times. For fast movement, run `reel frame REEL_DIR --t0 S --t1 E` and open the PNGs listed in the JSON in order. Each sheet runs left to right and top to bottom. The times printed below the pictures and the `pts_us` values in the JSON give their original presentation times in the Reel source. The first picture can predate S if it was still on screen. A frame first displayed at E falls in the next interval. These sheets show every decoded frame in the interval at a reduced size. Use `reel frame REEL_DIR --at S` to open one at source resolution. A snapshot can only return a frame from before its stopping point.
5. For a closer listen, run `reel listen REEL_DIR --t0 S --t1 S` or ask for its JSON alongside the page PNG and the matching rows from `stream.md`. These files work with any reader that accepts images and text. The WAV path points to the decoded mix on the machine running Reel. Readers with native audio input can use the WAV file.
   Each channel has a measured level and peak. In `level_changes`, a run marks consecutive 10 ms bins where power exceeds ten times the 20th percentile of power in that window. Read its start, peak and end on the film clock. A continuous sound can have zero such changes. The first and last runs remain visible when only eight fit.
   With cached AudioSet weights, Reel also estimates possible sounds on the Mac using up to ten seconds of context
   per window. Compare the candidates at recorded gain and after raising the playback level. A speech candidate
   gives you no words to quote. An empty list leaves the source open. With `--compare-sounds`, `neighbours` ranks similar sound descriptions. The search ranks a fixed vocabulary even when every match is poor. Keep a measured change, a possible source and an intelligible word separate in your answer.
6. If asked for an edit review, use the viewing log to describe distractions and give their times.

## What this does not give you

Fine facial expressions and small print can disappear on a page. A full-size frame lets you inspect them when the
source resolves them. The sound lanes describe changes and offer estimates of what made them. The pictures and text
alone cannot reproduce the experience of hearing a recording.

At a pause, use `compare-heard 0 2 4 6` to listen for something new or recurring across two intervals you have already heard. In MCP use `compare_heard` with the turn number, reference range and target range. Spectra and optional WAVs follow that order. `digital_silence_by_channel` is measured at the recorded sample rate. The local model listens at 16 kHz and can miss a sound or guess its source incorrectly. For files on disk, use `reel compare-heard TURN --reference 0 2 --target 4 6`.

If a sound reminds you of an earlier one, set `similarity=true` on that call. With `reel setup --compare-sounds` installed, the local CLAP audio encoder compares each original reference channel (matrix row) with each target channel (column). A larger cosine means the two entire recordings have more similar features. Two sources in the same room can share background sounds. A null cell means at least one of its channels has no signal at the encoder rate. The model hears the excerpt once and zero-pads to fit its input. Set `describe=false` to use this comparison without generating words. On the CLI add `--similarity`; at a playback prompt use `compare-heard --similarity 0 2 4 6`.

Pass your own descriptions to compare how well each fits the two recordings. For example, call `compare_heard(turn=3, reference=[0,2], target=[4,6], alternatives=["water flowing","metal tapping"], describe=false)`. In `sound_similarity.description_comparison`, rows follow the recorded channels and columns follow your descriptions. `target_minus_reference` subtracts mean cosine scores across each recording’s active channels. A rise measures a closer match to those words. The same encoder also compares 527 AudioSet descriptions if their vocabulary is installed. The nearest three per channel can suggest another explanation. Any of these labels may be wrong. When a recording has no signal at the encoder rate, the difference is null. Identical encoder features yield zero change. Replay either interval to investigate its source. On disk, use `reel compare-heard TURN --reference 0 2 --target 4 6 --recordings-only --alternatives "water flowing" "metal tapping"`.

For overlapping sounds, `layer START END RANK [CHANNEL]` at a pause replays the chosen recorded channel with one local estimate. On disk use `reel layer TURN --t0 2 --t1 5 --layer 2 --describe-sounds`. In MCP, `listen_layer` accepts either a rank or a free-text `focus`. The mix keeps its native sample rate and the estimate uses 16 kHz. Both cover the same film interval at recorded gain. In the reply, `original_rate_hz` and `original_samples` describe the mix WAV, while `rate_hz` and `samples` describe the 16 kHz analysis. Each rank is local to that interval and channel. If the text matcher picks the mix, only the mix is returned. A rank or text match cannot establish which events or speakers were present.

### Checking whether a client delivers the waveform

Configure `python examples/probe_audio_client.py clip.wav` as a stdio MCP server in the client you want to test. Use a short recording of a phrase known to the evaluator and ask the model to call `hear` and transcribe it. Repeat with a different phrase and a silent recording in fresh sessions. The tool returns only one WAV block. Inspect the client's tool receipt as well as the model's answer.

With local Codex CLI 0.165.0 and GPT-6.1 Terra, the receipt contained text saying the audio had been omitted on all four trials. A standard MCP client received the exact WAV bytes. Reel's local speech reader recovered the nine spoken words and returned no words for the silent clip. In a Reel response, `wav_attached` records what the server sent. Client delivery depends on the input path. [Measured receipts and answers](benchmarks/audio-client-probe.json)
