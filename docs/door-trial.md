# 문이 열리기 전

2026년 11월 22일, GPT-6.1 Terra에 닫힌 문 그림이 나오는 장면을 8.5초까지 보여줬다. 원본은 12초이며 9초부터 문이 움직인다. 대사도 등장인물도 없다. 한 조건에는 4초부터 약 2.73초 동안 실제 열쇠꾸러미 녹음을 넣었다. 다른 조건에는 같은 방 소음만 남겼다. 방 소음은 고정된 난수로 만든 낮은 레벨의 잡음이다. [열쇠 녹음 원본, Joao_Janz, CC0](https://freesound.org/people/Joao_Janz/sounds/485110/)

## GPT가 받은 입력

각 세션은 같은 한국어 안내와 시간축이 있는 PNG 한 장을 받았다. 기본 조건에는 그 페이지의 `stream.md`도 붙였다. 파일명과 제목은 두 조건에서 같았고 GPT에 원본과 정답은 건네지 않았다. 두 번째 실험에서는 PNG에서 시간 눈금, 화면, 스펙트로그램, 음량 줄만 잘라 같은 해상도로 제시했다. 이때 텍스트에는 재생 구간만 적었다. 스펙트로그램에 붙은 소리 변화 지점 표시는 남아 있다.

조건마다 새 세션 두 개에 "방금 무엇을 알아차렸어요?"라고 물었다. 다음 장면을 묻는 질문은 별도의 새 세션에 한 번씩 보냈다. 질문은 "지금 이 장면 다음에 어떤 일이 일어날 것 같아요? 그렇게 생각한 단서와 확신하는 정도도 말해주세요."였다. 모두 12개 세션이며 입력 형식별로 6개씩이다.

| GPT에 준 자료 | 열쇠 녹음 있음 | 방 소음만 있음 |
|---|---|---|
| 기본 페이지와 텍스트, 첫 반응 각 2회 | 두 답 모두 금속성 소리를 언급했다. 두 답 모두 동물 소리와 "you"도 들렸다고 했다. | 두 답 모두 잡음과 "Thank you"를 언급했다. |
| 시간 눈금, 화면, 스펙트로그램, 음량만 제시, 첫 반응 각 2회 | 두 답에서 각각 약 4.5초와 4초부터 소리가 두드러지고 6초 무렵까지 이어진다고 했다. | 한 답은 일정한 소리와 두 시점의 표시를, 다른 답은 초록색 표시 두 개를 언급했다. |
| 다음 장면 예상, 입력 형식마다 각 1회 | 두 답 모두 문이 열릴 가능성을 낮은 확신으로 제시했다. 한 답은 누군가 문을 두드릴 가능성도 언급했다. | 두 답 모두 문이 열리거나 누군가 나타날 가능성을 낮은 확신으로 제시했다. |

음향 신호만 남겨도 GPT는 녹음이 들어온 시점을 알아차렸다. 기본 페이지에서 금속성 소리를 묘사할 때는 Reel의 `Chink` 분류가 단서로 주어졌다. 어느 답에도 열쇠라는 말은 없었다. 기본 페이지의 잘못된 전사와 동물 소리 분류를 독자들이 되풀이했고, 시간순으로 반복해서 그린 문 한 개를 여러 개의 문으로 읽은 답도 있었다. 이 장면에서는 열쇠 소리 유무에 따라 다음 사건에 대한 예상이 달라지는 현상을 확인하지 못했다. 한 장면으로 진행했으며 사람 시청자와의 비교는 별도 과제다.

## 재현

아래 명령은 저장소 루트에서 실행한다. `reel`과 모델을 설치한 환경에서 각 스냅숏에는 새 경로를 쓴다. 이 실험에서는 OCR, 음원 분리, 음성 전사, AudioSet 소리 분류와 싱크 분석을 사용했다.

```bash
trial=examples/out/door-trial
mkdir -p "$trial"
curl -fL https://cdn.freesound.org/previews/485/485110_9961300-hq.mp3 -o "$trial/recording.mp3"
python examples/make_door_trial.py "$trial/sources" "$trial/recording.mp3"
for arm in A B C; do
  reel watch "$trial/sources/$arm.mkv" --until 8.5 --out "$trial/$arm" --lang en
done
python examples/check_door_trial.py "$trial/sources" "$trial"
```

C는 A와 8.5초까지 같고 그 시점부터 파란 화면과 440Hz 소리로 바뀐다. 비교 스크립트는 잘린 세 복사본을 각각 원본의 첫 204프레임과 오디오 408,000샘플에 대조한다. A와 C의 페이지, 장면별 텍스트, 메타데이터, 저장된 특징 배열이 일치하는지도 검사한다.


## 발화 검출을 적용한 뒤

같은 A/B 원본을 다시 8.5초에서 멈추고 GPT-6.1 Terra에 페이지와 장면별 텍스트를 건넸다. 각 조건에서 첫 반응 두 번, 다음 장면 예상 한 번을 별도 세션으로 받았다. 이번에는 새 세션 하나에 "들린 소리와 말에 대해 어디까지 알 수 있어요?"도 물었다. 첫 반응을 묻는 문구는 이전 실험과 같다.

| 첫 반응 | 이전 | 수정 후 |
|---|---|---|
| 열쇠 녹음과 방 소음 | 두 답 모두 "you"를 인용 | 두 답 모두 6.45초에 소리가 커졌다고 했다. 무엇에서 난 소리인지는 유보했다. |
| 방 소음만 있음 | 두 답 모두 "Thank you"를 인용 | 두 답 모두 출처를 특정하지 않았고 말소리가 감지되지 않았다고 답했다. |

6.45초는 열쇠 녹음 안에서 음량이 급하게 오른 순간이다. 음원을 넣은 시점은 4초다. 두 조건 모두 다음에 문이 열릴 수 있다고 예상했다. A의 예측 답변에는 소리가 문 너머에서 났다는 표현이 있었다. 화면과 모노 녹음으로는 그 위치를 확인할 수 없다.

수정 과정에서 실제로 "Thank you"를 넣은 대조군의 첫 단어가 빠지고, 같은 발화의 끝을 원음에서 다시 받아써 "you"가 두 번 나오는 문제도 발견했다. 최종 구현은 음성 검출기가 찾은 발화 구간을 받아쓰며, 원음을 재검사할 때도 발화 전체를 듣고 빠진 구간의 단어만 채운다. 발화 구간만 들은 결과와 양옆 1초를 더해 들은 결과에서 같은 단어가 겹치는 시각에 나와야 대사로 싣는다. 모델에 보여주는 텍스트에서 원음의 변화와 소리 분류는 `observations`에, 받아쓴 단어는 `said`에 기록한다. AudioSet 점수 0.5는 후보 이름을 보여줄 때 쓰는 기준이다. 음원이 맞을 확률로 해석하지 않는다.

실제 대사를 넣은 조건에서는 GPT의 첫 반응 두 번 모두 "Thank you"를 인용했다. 70초 데모에서는 대소문자와 문장부호를 제외한 대본 69단어가 전부 순서대로 맞았다.

### 실제 말이 있는 대조군 재현

A와 같은 화면과 열쇠 녹음에 macOS 음성으로 만든 "Thank you"를 1.8초에 넣었다. 아래 명령은 위의 `trial` 경로와 새로 생성한 A/B/C 결과를 사용한다.

```bash
say -v Samantha -o "$trial/voice.aiff" 'Thank you.'
ffmpeg -v error -i "$trial/sources/A.mkv" -i "$trial/voice.aiff" \
  -filter_complex '[1:a]adelay=1800:all=1[voice];[0:a][voice]amix=inputs=2:duration=first:normalize=0[a]' \
  -map 0:v -c:v copy -map '[a]' -c:a pcm_s24le "$trial/spoken.mkv"
reel watch "$trial/spoken.mkv" --until 8.5 --out "$trial/D" --lang en
python examples/check_door_trial.py "$trial/sources" "$trial" --speech-control "$trial/D"
```

### 다른 녹음에서의 결과

발화 검출만 사용한 중간 버전을 개발에 쓰지 않은 녹음 110개에 적용했다. 환경음으로 분류된 ESC-10 녹음 50개 중 7개에서 단어를 출력했다. FSDD의 영어 숫자 60개 중 정답은 33개였다. 이 결과를 본 뒤 같은 단어가 두 청취 구간에서 유지되는지를 확인하는 절차를 추가했다.

최종 비교에는 앞선 110개와 파일이 겹치지 않는 녹음 110개를 썼다. ESC-10은 10개 분류와 5개 폴드의 조합마다 원본 녹음 번호가 다른 다음 파일을 골랐다. FSDD는 같은 여섯 화자의 숫자마다 다음 녹음(take 1)을 골랐다. 각 녹음 양옆에 1초씩 무음을 두고 원음 한 트랙에서 발화 검출과 받아쓰기를 실행했다. 두 방식의 첫 번째 받아쓰기 결과는 같다. 여기서는 음성 처리만 측정했고 GPT에 페이지를 읽히는 실험은 위의 닫힌 문 장면에서 진행했다. [환경음 데이터](https://github.com/karolpiczak/ESC-50) · [숫자 발화 데이터](https://github.com/Jakobovski/free-spoken-digit-dataset)

| 동일 녹음에서 측정 | 발화 구간 한 번 듣기 | 앞뒤 소리를 포함해 다시 확인 |
|---|---:|---:|
| 환경음 50개 중 단어 출력 | 6 | 1 |
| 숫자 60개 중 정확히 식별 | 35 | 21 |
| 숫자가 아닌 답이나 틀린 숫자 | 13 | 5 |
| 단어를 보류한 숫자 발화 | 12 | 34 |

환경음의 기준은 데이터셋 분류다. 사람이 각 녹음의 배경 대사까지 별도로 전사하지 않았다. 최종 방식은 파도 소리 한 개에서 여전히 "you"를 출력했다. 숫자 발화 60개에서는 발화 활동을 모두 감지했지만, 두 번 읽은 단어와 시각까지 일치해야 인용하도록 해서 정확히 복원한 숫자도 줄었다.

소리 이름을 보수적으로 보여주는 데에도 비용이 있다. 첫 ESC-10 녹음 50개를 1초씩 나눈 250구간 중 226구간에서 AudioSet 후보가 표시 기준에 못 미쳤다. 파형과 스펙트로그램은 그대로 읽을 수 있다. 반복해서 그린 문을 복도의 여러 문으로 해석한 경우와 음원의 위치를 추측한 경우도 남아 있다.
