# 본 것과 들은 것을 다시 확인하기

문이 열리기 전에 오른쪽에서 가늘게 떨리는 소리가 들렸지만 무엇이 흔들렸는지는 모를 수 있다. Reel은 그때의 녹음, 화면, 채널과 처음 남긴 말을 함께 보관한다. 문이 열린 뒤 생각이 바뀌면 처음 기록에 새 판단을 연결할 수 있다.

| 하고 싶은 일 | 재생 중 쓰는 도구 |
|---|---|
| 눈에 띄는 변화나 짧은 소리 찾기 | `view`의 `attention`에서 사건 번호와 재생 시각을 확인한다. 전체 목록은 `recall_events`에서 읽을 수 있다. |
| 정체를 모르겠는 소리 기록하기 | `remember_event`에 사건 번호와 `unidentified`를 넘긴다. 목록에 없는 사건은 직접 시간 구간을 지정한다. 말소리는 들렸지만 단어가 안 들렸다면 `words_unclear`로 남긴다. |
| 같은 소리를 다른 채널에서 찾기 | `find_sound`에 앞에서 들은 구간, 나중에 찾을 구간과 두 채널 번호를 넘긴다. 같은 파형이 여러 곳에 나타날 수도 있다. |
| 배경이나 다른 소리에 묻힌 소리 다시 듣기 | `hear_change`는 앞선 배경, 뒤의 원음, 배경 주파수를 줄인 추정음을 돌려준다. `listen_layer`는 앞서 들은 예시와 닮은 소리를 혼합음에서 찾는다. |
| 어느 물체에서 났는지 살펴보기 | `inspect_event`의 `binding`은 소리만 듣고 쓴 설명, 스펙트럼과 사건 끝에 보인 전체 화면을 돌려준다. `ask_scene`으로 여러 구역의 움직임을 비교할 수 있다. |
| 거리와 가려짐 살피기 | `depth_at`에 두 화면 좌표를 주면 어느 쪽이 가까워 보이는지 추정한다. `picture_detail`에는 화면 무늬가 실제로 보인 구간들이 남는다. |
| 목소리, 말, 박자 구분하기 | `--voices`로 익명 화자 후보를 따라갈 수 있다. 단어는 시간 근거가 있는 전사에서 확인한다. 일정한 박자는 기계음에서도 검출될 수 있다. |
| 예상과 기억 확인하기 | 다음 구간으로 넘어가기 전에 `prediction`을 기록한다. 새 증거가 나온 뒤 앞서 한 예상을 지지하는지 반박하는지 연결한다. 되감기를 한 뒤 남긴 기록은 처음 본 시점과 구분된다. |

음원을 받는 클라이언트는 WAV를 재생할 수 있다. 그림과 텍스트를 받는 클라이언트는 스펙트럼과 로컬 모델이 원음을 듣고 남긴 설명을 읽는다. 같은 구간을 요청하면 두 방식 모두 그 시각까지 공개된 자료만 받는다.

## 설치와 기록 보관

```sh
pip install -e '.[mcp,voices,depth]'
reel setup --voices --depth
reel mcp film.mp4 --until 8.5 --voices --journal observations.sqlite
```

`--until`로 마지막 재생 시각을 정하고 `--journal`로 세션이 끝난 뒤에도 첫 판단과 수정 기록을 보관한다. `reel reports observations.sqlite`로 세션 번호를 찾고 `reel reports observations.sqlite --session ID --through-turn 4`로 네 번째 구간까지의 기록을 읽는다. 일반 재생에서 저장한 관측 목록은 `reel events DIR --turn 4`로 다시 열 수 있다.

## 얼마나 맞혔나

| 시험 | 실측 |
|---|---|
| 같은 녹음 다시 찾기 | 낯선 녹음 96개를 다른 소리와 섞고 위치, 크기, 극성을 바꿨다. 첫 후보의 위치가 96개 모두 정답에서 50ms 이내였다. 그중 79개가 강한 일치 기준을 넘었다. 원래 소리를 뺀 대조군 96개에서는 한 번도 넘지 않았다. |
| 다른 사람이 녹음한 같은 종류의 소리 고르기 | 43개 혼합음 중 25개에서 목표 음원이 더 선명해졌다. 15개에서는 더 흐려졌고 3개에서는 원음을 유지했다. SI-SDR 변화의 중앙값은 +5.8dB였다. |
| 다른 문장을 읽은 사람 알아보기 | 화자 14명 중 9명을 이전에 들은 목소리와 맞게 연결했다. 2명에게는 번호를 붙이지 못했다. |
| 화면의 지점 따라가기 | 사람이 영상에 표시한 574개 지점 중 142개 가까이에서 자동 추적을 시작했다. 29프레임 뒤에도 기준 거리 안에 남은 지점은 126개였다. 초기 좌표를 그대로 썼을 때는 119개였다. |
| 화면에서 더 가까운 지점 고르기 | DA-2K의 여덟 가지 유형에서 고른 이미지 64장으로 127쌍을 비교했다. 115쌍을 맞혔고 3쌍은 반대로 골랐으며 9쌍은 판단을 보류했다. |
| 자연스러운 현장 녹음에서 짧은 소리 이름 맞히기 | 사람이 표시한 사건을 정확히 맞힌 구간은 51개 중 3개였다. 기존 방식이 맞힌 두 구간을 유지했고 지나가는 자동차 소리를 한 구간 더 맞혔다. |
| 보거나 듣고 나서 자유롭게 설명하기 | 이번 청각 시험은 녹음 16개와 녹음당 사람 설명 5개를 사용했다. GPT의 설명이 해당 녹음을 다른 녹음과 구별하는 정도는 사람 기준 43.5%였다. 이전 값은 42.7%였고 이번 95% 구간은 19.6~66.0%다. |
| 같은 녹음에 대한 질문에 답하기 | GPT는 64문항 중 사람 다수 의견과 42개가 일치했고 3개는 틀렸으며 19개는 모른다고 했다. 같은 질문과 같은 증거에서 새 사건 단서만 뺀 대조군은 43개를 맞혔다. |

문이 열리기 전 8.5초만 들려준 로컬 Codex 시험에서 GPT는 열쇠가 들어간 녹음에 "날카로운 클릭 뒤 짧은 금속성 딸랑거림", 열쇠를 뺀 녹음에 "희미한 잡음", 무음에 "침묵"이라고 답했다. 어느 답에도 대사는 없었다. 문이 열린 뒤만 바꾼 영상은 GPT에 들어간 증거의 해시까지 같았다.

`python examples/check_event_paths.py`로 항목별 점수를 다시 계산할 수 있다. 사람과 같은 조건에서 새 시험을 할 때는 `examples/listener_study.py`로 첫인상, 질문을 미리 준 조건, 영상을 다시 보여주지 않는 지연 회상을 나눠 기록한다. [실제 답과 측정값](benchmarks/event-paths.json) · [시험 설계와 실행 예시](event-paths.md)

## 화면과 녹음을 바꾼 대조 시험

소리를 낸 물체가 보이는 영상 24개에서 움직임과 소리의 타이밍만으로 그 위치를 맞힌 경우가 없어 이 후보는 첫 화면에서 뺐다. 원음을 듣고 쓴 설명, 스펙트럼과 화면을 함께 받은 GPT는 두 장면에서 물체를 지목했다. 둘 다 물을 따르는 장면이었고 사람이 표시한 영역 안에 점을 찍은 것은 한 번이었다.

소리를 낸 물체가 보이지 않는 영상 24개에서는 GPT가 4번은 화면 밖이라고 답하고 20번은 판단을 보류했다. 같은 화면에 다른 종류의 소리를 붙인 대조군에서는 원래 정답 영역을 짚은 경우가 0/24였다.

문이 열리고 난 뒤의 내용만 바꾼 두 영상은 8.5초까지 공개한 화면 204장의 시각과 픽셀, 녹음 샘플, 관측 기록 171개가 모두 같았다. 이 Mac에서 데모의 처음 8초를 2초씩 네 번에 걸쳐 내보낸 시간은 세 번의 중앙값으로 기존 1.15초, 현재 1.53초였다. 음원에 이름을 붙이는 모델과 깊이 추정은 끈 상태로 측정했다.
